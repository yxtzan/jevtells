## 1. 什么样的人才算「画面里的人」

多人镜头判定、人脸禁区、卡片选边都改用同一个标准。一个检测到的人，要同时满足以下三条才算：

- 鼻子和至少一只眼睛的 visibility ≥ 0.5
- 这几个点都在画面内（离边缘至少 2%）
- 身体在画面内的可见高度 ≥ 画面高度的 35%

只露出肩膀、手臂、半张脸的旁人都不算。

## 2. 多人判定改为按时间段，不再按整个镜头

- 逐帧算出「画面里的人」的数量，平滑后，状态（单人 / 多人）变化持续 ≥ 1.5 秒才算真正切换。
- 竖屏：
  - 切镜点上直接切换。
  - 镜头内（比如黄仁勋那种推镜头）用 600ms（ease-in-out）在「完整画面」和「放大」之间做缩放动画。
- 字幕条模式在镜头内切换时同样跟着变化：完整画面时不另外显示字幕条。

**预期**：
- 黄仁勋：0–8 秒左右显示完整画面，推近后放大（和 v0.5.0 一致）
- Tim：两人同框的 1.1–4.0 秒显示完整画面，其余放大

## 3. 横屏卡片

人脸禁区只算第 1 节标准下「画面里的人」的脸。

**预期**：黄仁勋单人部分恢复完整卡片，放在右侧（和 v0.5.0 一致）。迷你卡片只在两侧完整卡片确实会压到人脸时使用。

## 4. 短窗口不闪

- OCR 和 SRT 导入的字幕同样执行 SPEC §6.5 的规则：短于 `min_window`（2 秒）的窗口和相邻窗口合并。
  - 只和**同一类**窗口合并（都要判定，或都是他人发言 / 主角不在画面）。
  - 不跨越他人发言、主角不在画面的边界。
  - 合并后的字幕用原文按顺序连起来，不改字。
- 合并后仍然短于 1 秒、并且不判定的窗口（比如 Tim 在说话时，主持人插了一句「是」）：
  - 面板继续显示上一个窗口的内容
  - 卡片不收起
  - 解说栏不切换成灰字
  - 这个窗口仍然不调用 API
- 窗口变了，所以两段素材都要重跑 judge 和 narrate（Jev 很便宜，记入预算）。

## 5. 切镜后的抖动动作

切镜后 0.3 秒（可配置）内开始的动作事件丢弃，原因记进 `actions.json` 的丢弃记录，比如 `settling_after_cut`。报告列出两段素材各丢了哪些事件。
