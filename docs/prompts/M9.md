# 任务：JevTells · M9 可视化界面（本地网页版）

**目标**：用户和开源用户不用终端，在浏览器里点几下就能把一段新视频做成成片。现在要手动填的参数，全部改成在界面上点选或框选：选主角、框水印、标「别人在说话」、标题。

**原则**：
- 界面只是命令行的外壳。生成时调用和 `jevtells run` 完全相同的流程，同样的参数必须得到同样的结果。
- 命令行的行为不变。

## 规则

- 没写清楚的地方选最简单的做法，写进报告的「偏离与决定」。每完成一项就跑测试、提交、推送。
- **只用 Python，不引入 Node 或前端构建工具。** 后端用一个轻量 Web 框架（Flask 或 FastAPI 二选一，报告里说明理由，依赖锁版本）；前端是 `src/jevtells/ui/` 下的纯 HTML、CSS、JS。不加载任何外部 CDN，断网也能打开。
- **只监听 127.0.0.1**，不能监听 0.0.0.0。
- **key 安全**：界面上只显示「已设置 / 未设置」。如果提供「设置 key」的输入框：输入框要遮挡显示，key 只写进本地 `.env`，绝不写日志、不回显、不出现在 URL 或报告里。
- 界面文字走 i18n（中文为默认，也要有英文）。视觉沿用项目的设计变量（INK 黑底、LIME 强调色、Noto 字体，见 `docs/design.md` §1）。
- 不许为某段素材写特殊处理。本轮 API 费用上限 0.10 美元。
- 分支 `m9-ui`，从 main 拉出；commit message 以 `M9:` 开头。不要合并，不要动 main。不得修改 README、CHANGELOG、LICENSE、`docs/`、版本号。

## A. 启动

- 新增 `jevtells ui [--port 7860]`：启动本地服务，并自动用默认浏览器打开页面。终端打印网址，按 Ctrl+C 退出。
- 打开后先跑一遍 `doctor` 的检查，结果显示在设置页；有阻断问题（比如缺 ffmpeg、缺模型、key 未设置）时，首页顶部给出提示和修复办法。

## B. 页面：分五步的向导，左侧是步骤栏

**1. 选素材**
- 可以把视频拖进页面（复制到 `samples/`，中文文件名自动转成安全的名字），也可以从 `samples/` 里已有的视频中选。
- 显示视频的时长、分辨率，以及一个可播放的预览。
- 分析范围：用起止时间的滑块，或者勾选「自动对准主角」（对应 `--start auto`）。默认分析全片（不是 30 秒）。

**2. 选主角**
- 显示一帧画面，画出检测到的每个人的框和编号（复用 `people` 和 `pick` 的逻辑），点一下就选中这个人。
- 有时间滑条，可以拖到切镜后的另一帧再点一次，添加锚点；已加的锚点列在旁边，可以删除。
- 填写「主角名字」（对应 `--speaker`）。
- 「用一句话描述选人」作为折叠起来的实验选项，需要 key（对应 `--target-desc`）。
- 勾选「人脸认人」（对应 `--face-identity`），默认勾选。

**3. 画面处理**
- 在画面上**拖拽画框**来模糊水印，可以画多个，也可以删除（对应 `--blur`，坐标自动换算成原视频像素）。框内实时预览模糊效果。
- 「原片已经有字幕」开关：用 M5 的字幕带检测结果预先勾好（对应 `--subtitles off`），旁边用一张截图标出检测到的字幕区域。
- 填写成片标题（对应 `--title`，默认「AI 读{名字}」）。

**4. 谁在说话**
- 先运行「预处理」，跑到字幕阶段（prepare、pose、track、asr 或 ocr、shots、segment），带进度条。
- 下方是一条时间轴：
  - 显示镜头切换点、缩略图条、每句字幕块（文字可以悬停查看）。
  - 主角不在画面的时段，用斜线纹自动标出来（来自 M6 的判断）。
- 交互：
  - 点一下字幕块，就在「主角说」和「别人说」之间切换；也可以在时间轴上拖拽，刷出一段「别人说」。
  - 播放器和时间轴联动：点哪里就跳到哪里。
- 结果换算成 `--others-speaking`。

**5. 生成**
- 显示所有参数的摘要，以及**等价的命令行**（可以复制，方便高级用户和排查问题）。
- 「生成」按钮：
  - 后台运行，逐阶段显示进度和日志，按阶段名高亮当前步骤。
  - 可以取消。
  - 显示本次 API 费用（从 `run_meta.json` 读取）。
- 完成后：横竖屏成片并排播放，提供下载按钮和「在 Finder 中显示」按钮。
- 页面上只调整标题、模糊、字幕这类渲染参数时，「重新生成」只重跑 render，不重新调用 API（沿用现有缓存机制）。

**设置页**
- `doctor` 的检查结果、key 的状态、是否设置 key。
- 默认语言、输出目录（默认 `work/`）。

**历史**
- 列出 `work/` 下已有的成片，可以播放、打开文件夹，可以「用这组参数重新打开」。
- 每次从界面运行，都把参数存成 `work/<clip_id>/ui_params.json`。

## C. 技术要求

- **把参数映射写成一个函数**：界面参数到命令行参数。界面和测试都用这个函数，保证两边一致。
- **长时间任务**：用子进程运行 `jevtells run`，把 stdout 实时推给前端（SSE 或轮询都可以）。同一时间只允许一个任务在跑。
- **大文件**：视频用流式传输；拖进来的文件写到 `samples/` 之前，先检查扩展名和大小（上限可配置，默认 2GB）。
- **路径安全**：只读写项目目录（或 `JEVTELLS_HOME`）下的 `samples/` 和 `work/`，拒绝 `..` 之类的路径穿越。
- **打包**：`pip install .` 之后，`jevtells ui` 也能用（前端文件作为包数据打进去）。

## D. 验证

1. **单元测试**：
   - 参数映射
   - 路径安全
   - 只绑定 127.0.0.1
   - key 不出现在任何响应和日志里
   - 时间轴的区间换算
   - 画框坐标换算（包括缩放显示时的换算）
2. **端到端**：通过界面的 HTTP 接口（不用真浏览器点击），把 Tim 这段按 `docs/samples.md` 的发布版参数走一遍。生成的 `windows.json`、`judgments.json`，以及成片的抽帧，要和用同样参数直接跑命令行的结果一致。可以复用缓存，不必重复调用 API。
3. **截图审查**：用真实浏览器打开每一步和设置页、历史页，截图保存到 `work/M9/screens/`。可以用 Playwright；如果装不上，用系统截图。每一步截一张，「谁在说话」的时间轴要用 Tim 这段的真实数据。
4. **用新手视角走一遍**：从「拖入视频」到「看到成片」，记录总共点了几次、哪里卡住了、哪里需要看说明，写进报告。
