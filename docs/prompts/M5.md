# 任务：JevTells · M5 打磨（通宵长任务）

这是一个**长时间无人值守**的任务：用户在睡觉，没人回答你的问题。你可能会因为额度用完被中途打断，之后由定时唤醒继续。所以本任务的规则和以前不同：

- **不要停下来提问。** 遇到本文没写清楚的地方，选最简单、最通用的做法，写进进度文件的「偏离与决定」，继续做。
- **小步提交。** 每完成一个小项：跑测试 → 提交 → 推送分支 → 在进度文件里打勾。这样任何时候被打断，都不会丢工作。
- **卡住就跳过。** 遇到真正的外部障碍（下载失败、权限、缺工具）：在进度文件里写 `BLOCKED: 原因`，跳到下一个不依赖它的项。**绝不用占位数据或绕路让它「通过」**，没证据的 ✅ 视为 ❌。
- **规则必须通用。** 不许按黄仁勋这段视频的时间、坐标、特征写特殊处理。

## 唤醒协议（每次开始工作，包括被定时唤醒、额度恢复后继续，都先做这一节）

1. 读 `work/M5_progress.md`（不存在就是第一次开始，按「开始前」创建它）。
2. 执行 `git status` 和 `git log --oneline -10`，确认当前在 `m5-polish` 分支。
3. 工作区有未提交的改动：说明上次做到一半被打断。先跑 `pytest`：通过就提交（message 写 `M5: WIP <项目编号>`）；不通过就找到做到一半的那一步，把它做完。
4. 从进度文件里**第一个没打勾、也没标 BLOCKED 的项**继续。已打勾的项不要重做。
5. 如果所有项都已打勾或标了 BLOCKED，并且 `work/M5_report.md` 已写好：**什么都不要再做**。回复一句「M5 已完成」，把 goal 标为完成，并停用本线程的定时唤醒；没有权限停用的话，在报告第一行写「请删除 M5 的定时唤醒」。

## 长任务规则

- **顺序**：按进度文件的顺序做。A 是 M4 的遗留问题，最先做；B 是 C 的基础；F 要在 A、B、C 之后做。D、E 和视觉部分无关，放在最后，时间不够就留到下次。
- **API 预算**：M5 全部调用 OpenRouter 的费用合计不超过 **0.30 美元**。每次调用后把费用累加进进度文件；快到上限就停止调用 API，改为只做不需要 API 的项。只改渲染的验证一律用 `--from render`，不要重跑 judge。
- **key 安全**：`.env` 里的 key 永远不要打印、不要 `cat .env`、不要 `env` / `printenv` 全量输出，也不要写进任何日志、报告、提交。
- **原素材只读**：`samples/` 下的原视频不要改动。新生成的素材放 `samples/synthetic/`，确认 `.gitignore` 覆盖它们（`.gitignore` 只能追加）。
- **质量优先**：宁可少做几项、每项做扎实，也不要每项都做一半。

## A. M4 遗留问题

**A1. 解说切换不重叠。** 现在新旧两句解说会叠在一起。改为先后进行：旧解说和旧引语先用 150ms 淡出，完全消失后，新的再淡入并上移 12px（250ms）。横竖屏都改。测试：在任意时刻，可见（透明度 > 0）的解说最多一句。

**A2. `run` 默认渲染。** `--until` 的默认值改为 `render`。`--until state` 仍然输出 `debug.mp4`。更新 `--help` 文字。

**A3. 解说句式多样化。** 黄仁勋现在的 7 句解说里，4 句以「双手」开头，3 句是「阐述「…」时」，4 句用了「全场最高 / 最低」，读起来像同一个模板。分三处改：

- **事实层**（`narrate_facts.py`）：「全场最高 / 最低」类亮点，全片最多保留 ⌈窗口数 ÷ 3⌉ 条，保留离全片均值最远的那几条，其余窗口不提供这类亮点（变化、持续、转变类亮点不受影响）。
- **提示词**：在 `config/narrate_prompt.md` 里给出 3–4 种开头方式（从动作开头、从引语开头、从数据变化开头、从声音开头），代码给每个窗口建议一种，相邻窗口不同。建议方式作为一个新变量传进提示词。
- **校验**（`narrate_validation.py`）新增两条：
  - 开头 2 个字：全片同一个最多出现 2 次
  - 「 前面的 2 个字（如「阐述」「强调」）：全片同一个最多出现 2 次，相邻两句不能相同

先只重跑黄仁勋的 narrate（judge 不重跑），在报告里贴出新旧解说对照。A6 之后还会从 state 起整体重跑一次，以那次的结果为准。

**A4. 页脚模型短名。** 页脚现在显示完整的模型 ID。在 config 里加一张映射表（如 `typesafe/jev-1.13*` → `Jev 1.13`，当前解说模型 → `Gemini Flash Lite`）；表里没有的，去掉厂商前缀和日期后缀再显示。完整 ID 照常写进 `run_meta.json`。见 design.md §6。

**A5. 解说区高度固定。** 解说区高度按全片所有解说里最多的行数确定，整片不变；单行解说时不留一大块空白，下面的内容也不跳动。见 design.md §5。

**A6. 远景不标。** 黄仁勋 2.33–2.83 秒（远景）有一个右手「抬手」误报（M4 报告第 6 节）。按 SPEC §7「远景」做成通用规则：镜头内主角的中位肩宽小于画面宽度的某个比例时，该镜头为远景，事件加 `far: true`，不进 state、不显示标签。阈值放 config；报告里写明你怎么定的阈值（例如列出各镜头的肩宽占比），**依据是远景下手部关键点的可靠性，不是为了消掉这一个事件**。此项会改变 state，需要从 state 起重跑黄仁勋（Jev 费用很低，记入预算）。

**A7. 渲染缓存跟随代码变化。** M4 时只改渲染代码要加 `--force` 才会重新编码，而 `--force` 容易误触发全部重跑。改为：渲染缓存的签名包含 `src/jevtells/render/` 下所有源文件的哈希，代码变了自动重渲染；`--from render` 一律重新渲染。

## B. 自适应布局

**B1. 镜头切分 + 每个镜头的主角范围。** 现在的 `shots.py` 只按「主角在不在画面」分段，没有真正的镜头切分。按 SPEC §6.4 重写：

- 相邻帧 HSV 直方图差异检测镜头切换（只用 OpenCV，不加依赖），阈值放 config；短于 0.5 秒的镜头并入前一个。
- 每个镜头输出 `target_box`（design.md §4.1 第 1 条）、`target_center_x`、`shoulder_px`、`far`。
- 在黄仁勋素材上，报告检测到的切换时间点，和你肉眼看总览图的结果对比。

**B2. 合成测试素材。** 黄仁勋的人物一直在画面中间，验证不了「人物偏左 / 偏右时怎么避让」。写 `scripts/make_layout_variants.py`，用 ffmpeg 从 `samples/jensen_panel.mov` 的 12–34 秒（单人段）生成到 `samples/synthetic/`：

| 文件 | 做法 | 用途 |
|---|---|---|
| `jensen_left.mp4` | 取原片 x 300–1280 的区域，右侧补深灰色（#202020）到 1280 宽 | 人物在约 28% 处 |
| `jensen_right.mp4` | 取原片 x 0–980 的区域，左侧补深灰色到 1280 宽 | 人物在约 75% 处 |
| `jensen_small.mp4` | 缩到 50%，四周补深灰色居中 | 模拟远景，验证 A6 |
| `jensen_cut.mp4` | 依次拼接 left 的 0–5 秒、right 的 5–10 秒、原片的 10–15 秒 | 镜头切换、卡片换边、重构图跳转 |

补边用纯色，不要用模糊的原画面（模糊的人也可能被检测成一个人）。四段都要跑完整流程（含 Jev，费用记入预算），合成素材不需要 `--blur`。每段先用 `people` 确认主角编号。

**B3. 布局调试图 + 违规检查。**（建议在 B4 之前做，开发 B4 时用得上）

- `--debug-layout`：每个镜头取中间一帧，输出一张调试图到 `work/<clip_id>/layout_debug/`，画出主角范围、各个禁区、候选位置、最终选中的位置。
- `scripts/check_layout.py`：逐帧检查成片里每个标签的矩形，是否压到主角范围、字幕条带、模糊区域、卡片、其他标签，统计违规帧数。验收要求违规帧数为 0；如果有兜底（fallback），单独列出。

**B4. 标签自动选位。** 按 design.md §4.1 实现，横竖屏通用（竖屏在 C 完成后也要用重构图后的坐标）。结果缓存到 `layout_<h|v>.json`。至少测试：两侧都有空间、只有一侧有空间（叠放且引线不交叉）、没有合法位置（兜底）、镜头切换时位置跳转。

**B5. 横屏判定卡片换边。** 按 design.md §4.2 实现：每个镜头决定一次，只在镜头切换时用 400ms 滑到另一侧；状态胶囊跟着换侧；标签按新禁区重算。用 `jensen_left.mp4` 和 `jensen_cut.mp4` 验证。

## C. 竖屏智能重构图

按 design.md §2b 实现，新增 `--reframe auto|off`（默认 auto，只影响竖屏）：

- 4:3 窗口，完整高度，按镜头固定；镜头切换时直接跳；镜头内只有主角明显移出时才慢慢平移。
- `--subtitles off` 时检测烧录字幕的水平范围，裁切窗口必须完整包含它。报告里写出黄仁勋检测到的字幕范围，并用截帧证明中英两行字幕都完整。
- 版式按 design.md §2b 的表格和 `design/D_v_reframe.html` 的 CSS 数值。
- 模糊先在原片坐标做，再裁切；标签、引线端点按裁切变换换算。
- `--reframe off` 保持 M4 的竖屏版式不变（回归测试）。
- 测试至少覆盖：裁切位置的计算（居中、靠边夹紧、字幕范围约束）、坐标变换、原片不比 4:3 宽时自动关闭。
