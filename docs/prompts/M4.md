## A. 新增的命令行选项

| 选项 | 作用 |
|---|---|
| `--others-speaking START-END`（可重复，单位秒） | 与该时段重叠 ≥ 50% 的窗口标记为 `speaker_other: true`。这些窗口**不调用 Jev 和写解说的模型**，judgments 和 narration 记为 null，并写明原因；state 照常生成；渲染按 design.md §5 处理 |
| `--blur X,Y,W,H`（可重复，原视频像素坐标） | 渲染时先对原视频帧的这些区域做高斯模糊，再叠加任何元素。模糊半径放 config。只影响成片，不改动分析阶段的输入 |
| `--subtitles on\|off` | 默认 on：在成片上画出转写字幕（样式自定，避开其他元素）。原片已烧录字幕时用 off |
| `--layout h\|v\|both` | 默认 both，输出 `output_h.mp4`（1920×1080）和 `output_v.mp4`（1080×1440） |
| `--title TEXT` | 竖屏顶栏标题，默认「AI 读{speaker}」 |

`--until` / `--from` 增加 `render` 阶段。只改渲染参数时，只重跑 render，不重新调用 API。

## B. 重写解说

现在的解说太平淡，例如「黄仁勋在白色背景前，通过手势解释……」。目标水平参考设计稿里的这句：

> 双手同时下压收住全句，说到「每一层都被重写」时自信度升至全场最高

做法是：代码先算出有依据的「事实」，模型只能用这些事实来写。

### B1. 事实计算（新建 `stages/narrate_facts.py`）

每个窗口生成一个 facts 对象：

- `index`、`total`：从 1 开始的编号
- `subtitle`、`previous_subtitle`
- `gestures`：中文描述列表。例如「左手下压（幅度大，表达欲 0.73）」。左右手同一时间做同一类动作时合并成「双手同时下压」。只放进 state 里的事件，不含 small 幅度的。
- `voice`：音量相对全片的变化、音调起伏、语速、停顿
- `judgments`：三个分数、意图（中文名和置信度）、情绪（中文名和置信度）
- `highlights`：**代码判定为真的**亮点句子。只能根据以下规则生成（阈值放 config），并且排除他人发言的窗口：
  - 某项分数在全片所有窗口中最高或最低 →「自信度 0.92，全场最高」
  - 某项分数和上一句相比变化 ≥ 0.08 →「自信度比上一句 +0.12」
  - 连续 2 句以上同方向变化 →「紧张度持续走高」
  - 意图或情绪和上一句不同 →「意图由「解释说明」转为「强调重点」」

### B2. 新的提示词（整体替换 `config/narrate_prompt.md`）

```
You write ONE line of on-screen commentary for a video-analysis overlay.
Return JSON only: {{"line": "...", "quote": "..."}}

FACTS for this sentence — the ONLY information you may use:
{facts_json}

Lines already shown earlier in this video (do not reuse their wording or opening):
{previous_lines}

Write "line" in {language_name}.

Rules for "line":
1. Chinese: at most 32 characters. English: at most 16 words. One sentence, no final period.
2. When possible combine, in this order: (a) a concrete movement taken from facts.gestures,
   (b) ONE short key phrase from facts.subtitle, faithfully translated, wrapped in 「」,
   (c) ONE item from facts.highlights.
3. If facts.gestures is empty, use the voice or a highlight instead. Never invent a movement.
4. Superlatives and trends ("全场最高", "持续走高", "回落", "转为") are allowed ONLY when the same
   statement appears in facts.highlights.
5. Do not start with the speaker's name, a pronoun, or a description of the scene/background.
   Name and scene are already on screen.
6. Neutral and descriptive. Never mock. Never claim lying, guilt, hidden motives, or mental states
   beyond the given intent/emotion labels. Never guess identity or private information.
7. Do not begin with the same 4 characters as any previous line.

Rules for "quote": an exact substring of facts.subtitle, 2–8 words, the most meaningful phrase.

Format example (invented facts, do not copy the content):
{{"line": "左手向外摊开，说到「下一代芯片」时专注度持续走高", "quote": "the next generation of chips"}}
```

### B3. 代码校验

不通过时，把失败原因附在提示词后面重试，最多 2 次；仍不通过就用模板兜底（「{第一个动作}，{第一条亮点}」）。校验项：

- 长度（中文按字符数）
- 语气红线词表（沿用 M3 的）
- 不以说话人名字、「他 / 她」、「在」开头
- 最多一对「」
- 出现「最高 / 最低 / 持续 / 回落 / 转为」时，必须能在 highlights 里找到对应的说法
- 前 4 个字不与之前任何一句相同
- quote 是字幕的原文子串，且 2–8 个词

重试次数和兜底次数写进 `run_meta.json`。

## C. 渲染器（`src/jevtells/render/`，拆成多个模块）

- 用 Pillow 逐帧绘制，通过 ffmpeg 管道编码，并 mux 回原音轨（沿用现有的编码器兜底逻辑）。
- 布局完全按 `docs/design.md` 实现。所有尺寸写成「设计尺寸 × 缩放系数」，颜色、字号、时长都放进 config 的 `render` 段，代码里不写死。
- **性能**：每个窗口里不变的部分（场外面板的静态内容）只画一次并缓存，每帧只重画会动的部分（引线、标签、正在过渡的数字）。在 M4 MacBook Air 上，30 秒片段每种画幅的目标是 3 分钟以内，报告实际耗时。
- 文字放不下时，先缩小字号（最小到原字号的 80%），再换行，绝不溢出。
- 解说里「」中的短语按设计稿高亮。
- 下载脚本补上所需字体：Noto Sans CJK SC 的 Bold 和 Black、Noto Serif CJK SC 的 Bold 和 Black，以及一款 OFL 授权的等宽字体。先验证 URL 再写进脚本。
