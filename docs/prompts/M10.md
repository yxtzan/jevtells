M10 的目标是把仓库公开、发布 v1.0.0。用户已经做了以下决定（2026-11-05）：

流程分三步：

1. Codex 完成这张卡的准备工作，交报告。
2. 总指挥审查、合并，改 README、CHANGELOG 和版本号，打 v1.0.0 标签。
3. 总指挥再写一张很短的 `M10-publish.md`，Codex 按它推送并公开仓库。

## 规则

- 开始时先执行 `git push origin main --follow-tags`。从 v0.7.0 起的 main 和标签都还没推送。推送失败就停下来写进报告，**不要强制推送**。
- 分支 `m10-release`，从 main 拉出；commit message 以 `M10:` 开头。不要合并，不要动 main。
- **不得修改** README、CHANGELOG、LICENSE、版本号，以及 `docs/` 下除 `docs/images/` 以外的文件。README 由总指挥写；你需要的文案素材和数据写进报告。
- **不得把仓库改成公开**，也不要改 GitHub 上的任何设置。
- 不提交视频。GIF 只放 `docs/images/`。
- 不要停下来提问。没写清楚的地方自己判断，写进报告的「偏离与决定」。每完成一项就跑测试、提交、推送分支。
- 每次 `git commit` 前先看 `git status`。如果出现「全部删除 + 全部未跟踪」，是 Cursor 把索引弄坏了，先执行 `git reset -q` 再提交。

## A. 从 GitHub 全新安装（最重要）

按陌生人第一次使用的方式走一遍，**不使用现有的 `.venv`、`models/` 和 `assets/fonts/`**：

1. 在临时目录里 `gh repo clone yxtzan/jevtells`，按 README 的安装步骤一字不差地执行：建虚拟环境、`pip install`、`jevtells download`、`jevtells doctor`。
2. 把 `samples/tim_interview.mov` 复制进去，走两条路：
   - **命令行**：照 README 的命令行示例跑完一段，到出成片为止。
   - **界面**：`jevtells ui` 换一个端口，从拖入视频到出成片走一遍。
3. 两条路都需要 key 时，从项目目录的 `.env` 复制过去即可。**不要把 key 打印出来，也不要写进日志或报告。**

在报告里逐条记录：

- README 里每一处写错、漏写、需要猜的地方，给出原文和建议改法。
- 每一步的耗时，以及下载了多大的文件。
- 所有报错的原文（去掉 key）。

**只记录，不改 README。** 如果是代码问题导致装不上或跑不通，可以在分支上修，并写进报告。

## B. 短素材漏检烧录字幕

M9b 的新手走查用的是 4 秒素材 `samples/m9_novice.mov`，从 Tim 原片截出，原片有烧录字幕。但 `/api/inspect` 返回 `bounds` 为空，界面没有自动打开「原片已有字幕」，结果成片里出现了两层字幕。

1. 先查清原因：是采样帧太少、阈值不合适，还是别的问题。报告里写明证据。
2. 如果能**通用地**修好，就修。修完后，下面每段素材的检测结果都要和修改前一致，或者更准，在报告里列表对照：
   - `tim_interview.mov`
   - `jensen_panel.mov`
   - `leijun_areyouok.mov`
   - `m9_novice.mov`
   - 截取长度分别为 3、5、10 秒的片段各一段
3. 不许出现「4 秒以下就默认有字幕」这类针对样片的规则。如果修不好，就说明原因并保持现状，由总指挥决定界面上怎么提示。
4. 加回归测试。
